# 02. どうしたらAIで切り抜きができるか ― 調査と設計

## 1. 調査結果（既存ツールの共通パターン）

既存のAI切り抜きツール（OpusClip系の商用ツール、OSSの AI-Youtube-Shorts-Generator、
Smart Clip MCP、OpenShorts など）はほぼ同じパイプラインを持つ。

```
ASR(Whisper) → 文字起こしをLLMで採点 → 音声の手がかり(音量・笑い・沈黙) → 縦型リフレーム → 字幕焼き込み
```

調査で分かった重要な知見:

1. **文字起こし全文をLLMに丸投げするだけでは弱い。**
   「面白い」の定義が曖昧なため、ブレる・見落とす。
   → **チャンク分割＋採点ルーブリック** で評価させるのが有効。
2. **音声は「どう言ったか」を教えてくれる。** テキストは「何を言ったか」しか分からない。
   → 音量の急上昇（叫び・笑い声）は強い補助シグナル。
3. **境界（どこで切るか）は沈黙検出で吸着させる** と自然になる。
4. **LLMのみの選択は映像のエネルギーを見ていない** という指摘がある。
   → 音声・テキストの数値シグナルと組み合わせる（ハイブリッド）。
5. 人間の最終チェックは前提にする（候補を理由付きで提示する）。

## 2. 「最強」の定義

01で整理した「上手い切り抜きの5条件」を、それぞれ機械で測れる形に落とす。

| 条件 | AIでの実現方法 |
|---|---|
| ① フック | 候補内で最もスコアが高い発話を特定 → 必要なら冒頭にティーザー挿入。LLMがフック文を評価 |
| ② 単体で成立 | 開始点を「文頭」に吸着。LLMが「文脈なしで分かるか」を採点し、開始点を前倒し提案 |
| ③ オチ | 盛り上がりピークの**後ろ**で終わるよう終了点を決定＋余韻 |
| ④ テンポ | 沈黙検出 → ジャンプカット |
| ⑤ テロップ | 単語/文単位タイムスタンプ → 14文字折返しのASS字幕、強調語ハイライト |

## 3. アーキテクチャ

```
           ┌────────────┐
 動画 ───▶ │ transcribe │  faster-whisper / 既存のSRT・JSON
           └─────┬──────┘
                 ▼
           ┌────────────┐   ┌────────────┐
           │  audio     │   │  text      │
           │ 音量(1秒毎)│   │ 笑い/驚き語 │
           │ 沈黙区間   │   │ 発話密度   │
           └─────┬──────┘   └─────┬──────┘
                 └──────┬─────────┘
                        ▼
                 ┌────────────┐
                 │ candidates │  ピーク中心に文境界で窓を作る（15〜60秒）
                 └─────┬──────┘
                       ▼
                 ┌────────────┐
                 │  scoring   │  ヒューリスティック総合点＋重複除去(NMS)
                 └─────┬──────┘
                       ▼
                 ┌────────────┐
                 │  llm(任意) │  Claude がルーブリック採点・境界調整・タイトル/フック生成
                 └─────┬──────┘
                       ▼
                 ┌────────────┐
                 │   edit     │  ジャンプカット→縦型→字幕→タイトル帯→ラウドネス
                 └─────┬──────┘
                       ▼
                 clips/*.mp4 + report.json/md
```

設計方針:

- **LLMなしでも最後まで動く。** APIキーが無い環境ではヒューリスティックだけで選ぶ。
  LLMはその上に「再ランク＋文章生成」として乗る（品質を上げる層であり、単一障害点にしない）。
- **LLMには候補だけを渡す。** 全文丸投げではなく、数値シグナル付きの候補窓とその前後文脈を渡し、
  ルーブリックで採点させる（調査知見1への対策）。
- **構造化出力（JSON Schema）** で受け取り、パース失敗で落ちないようにする。
- **ffmpegだけで編集を完結。** 外部GUIに依存しない。

## 4. スコアリング設計（レビューを経た現行版）

### 4.1 1秒ごとの「盛り上がり度」 excite(t)

手がかり（すべて 0〜1）:

| 手がかり | 中身 | 最大寄与 |
|---|---|---|
| loud | 局所ベースライン（前後60秒の中央値）からの音量の跳ね | 0.55 |
| react | 文字起こし中の笑い・驚き語（草, w, 笑, やばい, うそ, ！？ …） | 0.60 |
| density | 発話密度（早口＝興奮） | 0.25 |
| chat | コメント速度が普段の何倍か（8倍で満点）× 反応語の割合。視聴者の反応遅延5秒を補正 | 0.75 |

**ノイジーOR** で結合する:

```
excite = 1 − (1 − 0.55·loud_eff)(1 − 0.60·react)(1 − 0.25·density)(1 − 0.75·chat)
```

- どれか1つが強ければ山場になり、複数が重なるほど確信が増す（足し算だとチャットだけの山場を取りこぼした）
- **音量の裏取り**: `loud_eff = loud × (0.4 + 0.6·裏付け)`。裏付け＝±3秒以内の笑い語かチャット反応。
  BGMや効果音で「うるさいだけ」の区間を山場と誤認しない

### 4.2 候補窓

1. excite のピーク（近傍5秒で最大・上位25%以上）を列挙
2. ピークを含む文〜2文後を終了候補、尺が範囲内になる文頭を開始候補として全組み合わせを採点
3. **他の山を取り込む窓は捨てる**（自分のピークより強い山が窓内にあると、点数を借りて本命と重複し両方潰れる）

### 4.3 窓のスコア

```
score = 0.40·peak + 0.25·hook + 0.20·mean + 0.15·payoff + 0.06·setup
      − 尺の罰（長すぎ0.2 / 短すぎ0.04、目標30秒）
      − 沈黙の罰
      − 切り際の罰（直後3秒がまだ盛り上がっている＝途中で切った / 直前3秒が別の山の余韻）
      + 文頭が間の後なら加点、「で、」「だから」等の接続詞で始まるなら減点
```

### 4.4 選定

- 重なり30%超は低い方を除外（NMS）
- **品質下限**: 総合点が1位の50%未満、または山の高さが1位の50%未満なら出さない（数合わせの駄作を出さない）

### 4.5 編集

- 長い沈黙(0.6秒以上)を0.15秒に詰めるジャンプカット
- フックが弱い（冒頭の盛り上がりが山の60%未満）ときは山場を最大3秒、冒頭にティーザーとして挿入
- 9:16 ぼかし背景、上部タイトル帯、冒頭のフック文、強調語を黄色にしたASS字幕
- 字幕の改行は動的計画法（助詞の後で切る・禁則・行長を揃える）
- 2パスのラウドネス正規化（-14 LUFS）
- 山場フレーム＋タイトルのサムネイル

## 5. LLM（Claude）ルーブリック

各候補を次の観点で0〜10点採点させる:

1. hook: 最初の3秒で掴めるか
2. standalone: 元配信を知らなくても分かるか
3. payoff: オチ・感情のピークがあるか
4. emotion: 笑い/驚き/感動の強さ
5. shareability: 誰かに送りたくなるか

さらに次の項目を出力させる:
- 調整後の開始・終了時刻（文境界の中から選ぶ）
- タイトル（18文字前後）
- フック用の一言（冒頭テロップ）
- 強調すべきキーワード
- 選定理由

## 6. 評価方法（レビューの基準）

- 合成テスト動画（既知の「盛り上がり」区間を仕込んだもの）で、検出位置が正解区間と重なるか
- 境界が文の途中になっていないか
- 出力動画が 1080x1920・音声あり・字幕あり・尺が範囲内か
- 単体テスト（pytest）でロジックの回帰を防ぐ
