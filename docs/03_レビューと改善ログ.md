# 03. レビューと改善のログ

「作る → レビュー → 改善点を見つける → 直す」を繰り返した記録。
各回とも、合成配信（正解区間を仕込んだ疑似データ）と実際の出力動画・画像で検証した。

---

## 第1回: 初期実装の通し実行

**やったこと**: 180秒の疑似配信（118〜134秒に「待って→うそでしょ→やばい→草→爆笑」を仕込む）で end-to-end 実行。

| 確認項目 | 結果 |
|---|---|
| 1位が正解区間を含む | ✅ 119.2〜135.3秒 |
| 1080x1920・音声あり | ✅ |
| 字幕・タイトル帯の表示 | ✅（画像で目視） |
| ラウドネス | ⚠️ -14.1 LUFS は良いが、別クリップで -16.5 LUFS |
| 2位・3位 | ❌ 普通の雑談が「数合わせ」で出力される |

**見つかった問題 → 修正**

1. 数合わせの駄作が出る → **品質下限**（1位の50%未満は出さない）
2. ラウドネスが短いクリップでずれる（1パス loudnorm の限界） → **2パス測定 → 線形補正**
3. 山場の直前から始まり「何が起きたか」の前フリが無い → **setup（前フリ）加点**
4. 人間の切り抜き師が最初に見る「コメントが流れた所」を使っていない → **チャット信号**を追加（yt-dlp の live_chat.json 対応、視聴者の反応遅延を補正）
5. テスト素材のバグ（長い沈黙が実際には仕込まれていなかった）を修正
6. Claude 連携は API キーが無い環境のため、偽クライアントで「スコア反映・境界調整・存在しない強調語の除去・失敗時のフォールバック」を検証

## 第2回: 実際に使う人の目線でコードを読み直す

| 問題 | 修正 |
|---|---|
| Claude が作る「冒頭の一言(hook_text)」を生成するだけで表示していない | 冒頭に大きくポップイン表示 |
| サムネイルが無い（人間の手順⑨が抜けている） | 山場フレーム＋大タイトルのサムネイル生成 |
| URL を直接渡せない（素材集めが一番面倒） | yt-dlp で動画・チャット・字幕を一括取得 |

## 第3回: 出力画像の目視レビュー

- サムネイルが「油断した瞬間に**完｜全**敗北する配信者」と単語の途中で改行されていた
  → **日本語改行を動的計画法で作り直し**（助詞の後ろで切る・漢字/カタカナ連続の途中を避ける・禁則・行長を揃える）
  → 「油断した瞬間に｜完全敗北する｜配信者」
- 字幕を `[:2]` で2行に打ち切っており、長文だと**文字が黙って消えるバグ**を発見・修正

## 第4回: 意地悪な素材での頑健性テスト

実配信にある2つの罠を仕込んだ:
- **大音量BGM**（25〜42秒、話し声は普通）… うるさいだけで面白くない
- **チャットだけが沸く場面**（150〜160秒、声は普通）… 画面上の出来事に視聴者が反応

| 指標 (excite) | 修正前 | 修正後 |
|---|---|---|
| BGMの罠 | 0.56 | 0.31 |
| 本命の山場 | 0.78 | 0.94 |
| チャットのみの山場 | 0.08〜0.39 | 0.73 |
| 平常時 | 0.11 | 0.13 |

**見つかった問題 → 修正**

1. 足し算の結合だと「どれか1つが強い」山場を取りこぼす → **ノイジーOR 結合**
2. 音量だけの区間が高得点 → **音量の裏取り**（近くに笑い語/チャット反応がある時だけ満点）
3. チャットの基準を中央値+MADで取っていたため、盛り上がりの多い区間で基準が引き上がる
   → **「普段（40%点）の何倍の速さか」** で評価
4. **候補窓が隣の山の点数を借りる構造バグ**: 152秒の山の窓が126.9秒から始まり、本命と重複判定されて消えていた
   → 自分より強い山を含む窓は捨てる
5. 総合点は前フリ/オチの加点で底上げされる → **山の高さにも下限**
6. **盛り上がりの最中で切っていた**（payoff が「早く切るほど得」になっていた）
   → **切り際の罰**: 直後3秒がまだ盛り上がっていれば減点、直前3秒が別の山の余韻なら減点
7. 尺の罰が対称で、前置き16秒を足して目標尺に寄せていた → **長すぎは重く、短すぎは軽く**（目標30秒）

**結果**: BGMは一度も選ばれず、チャットのみの山場を区間ごと検出、本命は笑いが収まってから終わる。
これらはすべて回帰テスト（`tests/test_e2e.py`）として固定した。

## 第5回: 速度

1時間の音声で、デコード+RMS 3.7秒 / 盛り上がり度 0.1秒 / 候補生成 0.01秒。
ボトルネックは文字起こし（Whisper）のみで、解析部分は長時間配信でも問題ない。

## 現状の限界と次の改善候補

| 優先度 | 内容 |
|---|---|
| 高 | 実配信データ（文字起こし＋チャット＋人間が選んだ切り抜き）での評価セット作成と重みのチューニング |
| 高 | Claude 再ランクの実API検証（この環境では API キーが無く未検証。偽クライアントでのみ検証済み） |
| 中 | 話者の顔・ゲーム画面の重要領域を追う縦型リフレーム（現状はぼかし背景のレターボックス） |
| 中 | 笑い声の音響検出（文字起こしに出ない笑いを拾う） |
| 中 | 話者分離（コラボ配信で「誰のリアクションか」） |
| 低 | 効果音・BGMの自動挿入（権利に注意） |
